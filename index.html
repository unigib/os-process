04 / BEYOND THE MODEL

How memory grows

Heap: A call to malloc() first tries to reuse available memory. If the allocator needs more, it can make a system call asking the OS for more virtual address space; on Linux, for example, it may use mmap() or brk(). The OS can then add or extend a mapping in the process's address space.

Stack: The stack pointer moves as functions are called and return; it is not fixed. On systems with a growing stack, accessing memory beyond the currently usable stack pages can cause a page fault. If the access is valid and within the stack's limits, the OS can extend the usable stack; otherwise the process may encounter a stack overflow.

Physical memory: A virtual mapping does not necessarily mean physical memory has been provided immediately. Accessing a mapped page can trigger a page fault, allowing the OS to supply a physical page. Details vary by OS and configuration.

The process uses virtual addresses, not a fixed-size container. Real allocation and stack growth depend on the platform and available resources and can fail before the regions meet. The six-block and six-call limits above are only for this simulation.

How can a machine run out of memory?

Imagine a process repeatedly allocating and writing to large blocks. This is an illustrative sequence, not a measurement of this machine:

  1. 1 / Request

    The allocator can ask the OS for more virtual address space.

  2. 2 / Use

    Writing to the blocks can cause page faults, prompting the OS to supply RAM.

  3. 3 / Pressure

    As memory fills, the OS can reclaim pages and may move some to swap on disk, if available. Swap is slower and finite.

  4. 4 / Limit

    If resources run out, allocation may fail or the OS may terminate a process, depending on its policy.

Limits on virtual address space or on a process can also stop allocation earlier. Virtual memory does not create unlimited physical storage.

05 / CONNECT THE CONCEPTS

The C behind the concepts

REFERENCE CODE · C

This complete program illustrates the same ideas as the controls above. It is an example, not code executed by the simulation.

process_example.cREFERENCE ONLY
#include <stdio.h>
#include <stdlib.h>

void push_stack_frames(int level) {
    int local_marker = level;       // Local to this call
    printf("Level %d\n", local_marker);

    if (level < 3) {
        push_stack_frames(level + 1); // Another stack frame
    }
}                                   // This frame returns

int main(void) {
    char *block = malloc(64);       // Allocate on the heap
    if (block == NULL) {
        fprintf(stderr, "Allocation failed\n");
        return 1;
    }

    block[0] = 'A';                 // Use the allocated memory
    push_stack_frames(1);            // Call levels 1, 2 and 3
    printf("Block: %c\n", block[0]);
    free(block);                    // Release the allocation
    return 0;
}
01

Allocate

malloc(64) requests 64 bytes on the heap. The pointer block is a local variable, not the allocated block itself.

02

Call & return

Each recursive call typically adds a stack frame with its own level and local_marker. Frames are removed as calls return.

03

Free

free(block) releases the heap allocation after the calls finish. Try the same actions with the controls above.
